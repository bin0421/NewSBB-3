[2] 결정 사항
-------------
1. 개발 환경 : 참조와 동일하게 JDK 25 (Temurin 25.0.5) / Spring Boot 4.1.2 / Gradle 9.8.2 (Kotlin DSL) / H2.
2. 패키지·루트 프로젝트명은 강사 저장소와 동일하게 com.back / back (build.gradle.kts description 만 NewSBB).
3. 참조 기준 : 강사 저장소 jhs512/p-14172-2 의 056-3 커밋(56강 끝) 상태의 코드 구조·응답 형식을 따른다.
   - REST API(/api/v1/posts, /api/v1/posts/{postId}/comments), RsData 응답, ResponseAspect, GlobalExceptionHandler.
   - 테스트는 @ActiveProfiles("test") + @SpringBootTest + @AutoConfigureMockMvc + @Transactional.
4. TDD : 참조는 기능을 먼저 만들고 33강부터 테스트를 쓰지만, 이 저장소는 기능마다 테스트를 먼저 커밋한다.
   - -1 : 테스트 추가 (실패) / -2 : 구현 (통과) / 필요할 때만 -3.
   - 테스트만 넣은 커밋은 빌드가 실패한다. 커밋 전에 "의도한 이유로" 실패하는지 확인하고 README 에 실패 이유를 적는다.
   - 테스트는 그 단계를 실패시키는 데 필요한 것만 검사한다. 참조 테스트에 없는 검사를 넣으면 README 에 이유를 적는다.
5. 참조 순서를 그대로 따르지 않고 재구성한다 : 설정·엔티티 -> 샘플 데이터 -> 글(다건·단건·404·작성·검증·수정·삭제) -> 댓글(다건·단건·작성·수정·삭제).
6. 404·검증 실패·잘못된 JSON 처리(참조 48~52강)도 글 기능 안에서 TDD 로 넣는다.
7. 강사 저장소의 BackApplicationTests(contextLoads)는 넣지 않는다. 테스트는 모두 test 프로필(메모리 DB)로 돈다.
8. README 개발일지 형식 : 링크 -> 원인 -> 작업 -> 설명 (템플릿 기본).
9. 커밋 메시지 : "번호 + 명사형 제목" 한 줄. 단계 목록 승인 후 단계마다 묻지 않고 커밋 -> main 푸시한다.
   참조가 헷갈리거나 목록 밖의 결정이 생기면 멈추고 묻는다.
